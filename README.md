# 80分 AI 比赛

写一个会打 80分(上海规则)的程序,和别人的程序打联赛。

**你写的只是"决策"这一半。** 发牌、判合法、记分、升级都由裁判负责。但**规则要你自己实现** —— 裁判不会借给你任何工具,你手上有的就是一本 [`RULES.md`](RULES.md)。

## 1. 你要交什么

**一个目录**,入口是 `index.js`。里面想放几个文件都行 —— 你要装下自己写的规则引擎,一个文件多半塞不下。

```
my-ai/
  index.js        ← 入口,必须有
  engine.js       ← 你自己照 RULES.md 写的规则实现
  strategy.js     ← 随你怎么拆
```

`index.js` 导出一个**不收参数**的工厂:

```js
module.exports = () => ({
  name: '你的名字',
  onDeal(view)        { return null; },
  onRebel(view)       { return false; },
  discard(view)       { return view.hand.slice(0, 8); },
  lead(view)          { return [view.hand[0]]; },
  follow(view, plays) { return view.hand.slice(0, plays[0].cards.length); },
});
```

复制 [`example/`](example/) 开始改。

### 怎么交

1. **Fork 这个 repo**
2. 把你的目录放进 `submissions/<你的名字>/`,例如 `submissions/zhang-san/index.js`
   * 目录名用英文小写和连字符,一个人只交一个
   * 别改 `submissions/` 以外的任何文件 —— 改了的 PR 会被退回
3. **提 PR** 过来

截止之后我们把所有提交拉下来,在同一台机器、同一批牌上跑联赛。

**交之前自查两条**(见 [§7](#7-怎么开发)):`RULES.md` §S5 的自测向量全过;
自己跑几场完整对局,确认不抛异常。

### 你的代码跑在什么环境里

一间**只有 JS 内建的空屋**:

| 有 | 没有 |
|---|---|
| `Object` `Array` `Math` `JSON` `Map` `Set` `Promise`… | `require('fs')` / `require('http')` / 任何 node 内置模块 |
| `require('./别的文件.js')`(你自己目录里的) | `process`、环境变量、命令行参数 |
| `console.log`(会带上你的名字前缀) | npm 依赖 —— **一个都不能用** |

纯 JavaScript,不能读写文件,不能联网。想预计算一张表就写进代码里。

**没有随机源也是有意的**:`Math.random` 在你屋里可用,但用了会让你的成绩不可复现、申诉时无法回放。要随机就自己带一个种子发生器。

### 时间

每次调用都计时。裁判不会中途打断你(同步调用打断不了),但总用时会公示,**超出基准选手 3 倍的提交不进决赛**。一场平均 30 局、每局 100 手左右,自己算算预算。

## 2. `view` —— 你能看到的一切

这是唯一的信息入口。**没有别的口子**:看不到别人的手牌,看不到还没发的牌,看不到底牌(除非你是庄家)。

`view` 和里面每一张牌都是**冻结**的。你改不动 —— 想改就先自己拷一份。

### 牌长什么样

```js
{ suit: 'S'|'H'|'D'|'C'|'X', rank: 2..16, id: 0..107 }
```

* `S`♠ `H`♥ `D`♦ `C`♣,`X` 是王
* `rank`:数字牌 2–10,`11`=J `12`=Q `13`=K `14`=A;王的 `rank` 是 `15`(小王)`16`(大王)
* **两副牌 108 张**,所以每种牌都有两张,花色点数完全相同 —— **`id` 才是唯一标识**,判重、比较、返回都用 `id`

裁判**只认 `id`**。你返回什么形状的对象都无所谓,它按 `id` 去自己那份手牌里取真牌。所以伪造牌面既无害也无用。

### 每个阶段都有的字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `phase` | `'deal'｜'rebel'｜'discard'｜'lead'｜'follow'` | 这次问的是哪件事 |
| `seat` | `0..3` | 你的座位。**0=南 1=东 2=北 3=西**,`(seat+1)%4` 是你下家(逆时针) |
| `myTeam` | `0｜1` | `seat % 2`。你的队友坐 `(seat+2)%4` |
| `hand` | `Card[]` | **你自己**的手牌。`deal` 阶段只有已经发到你手上的那几张 |
| `trumpRank` | `2..14` | 本局打几 |
| `trump` | `{suit, rank}｜null` | 主。`suit === null` 是**无主局**。`deal` 阶段恒为 `null` |
| `declSeat` | `0..3｜-1` | 庄家。`deal` 阶段恒为 `-1` |
| `curDecl` | `{seat,suit,strength}｜null` | 当前谁亮了什么 |
| `rebelHappened` | `boolean` | 已经有人用王对反过 —— 之后不能再加固 |
| `dealerKnown` | `boolean` | `false` = 无庄局,各家按自己队的级数抢亮,最终亮主者坐庄 |
| `dealer` | `0..3｜-1` | 本局庄家(无庄局为 `-1`) |
| `firstTaker` | `0..3` | 先拿牌的那家 |
| `levels` | `[l0, l1]` | 两队级数。`levels[view.myTeam]` 是你队打到几 |
| `played` | `[p0, p1]` | 各队**坐庄守住过**的最高级数,没有则 `-1`。必打关卡要用 |
| `gates` | `number[]` | 必打关卡,默认 `[2,5,10,13]` |
| `round` | `number` | 整场的第几局(0 起) |
| `kittySize` | `8` | 底牌张数 |
| `history` | `Play[]` | 已出的牌,见下 |
| `buriedKnown` | `Card[]` | 底牌 —— **只有庄家非空**,别人恒为 `[]` |

分阶段还会多给:

| 阶段 | 多给 |
|---|---|
| `rebel` | `rebelReason: {pts, nT, byPts, byTrump}` —— 你凭什么够格造反 |
| `lead` / `follow` | `trickNo` —— 第几墩(0 起) |

### `history` —— 最容易写错的地方

它是**扁平**的 `{seat, cards}` 数组,不是按墩分好的。

* **每连续 4 个元素是一墩**,其中第一个是那墩的领出
* 一手可能是多张(对子、拖拉机、甩牌),但**一墩永远是 4 手**,不管每手几张
* `history.length % 4` 就是本墩已经出了几手
* 你在 `follow` 里拿到的 `history` **已经包含**本墩前面几家出的牌

按墩切开:

```js
const tricks = [];
for (let i = 0; i + 4 <= view.history.length; i += 4)
  tricks.push(view.history.slice(i, i + 4));
```

## 3. 五个方法

### `onDeal(view) → {suit, strength} | null`

发牌是**逐张**的,每发到你手上一张就问你一次 —— 一局 100 次。发完之后还会绕圈再问,直到一整圈没人动作(上限 4 圈),所以"最后一张到手才够格亮"也来得及。

返回 `null` = 这次不亮。返回一个选项 = 现在就亮。

`strength` 的含义:

| 值 | 什么 | `suit` |
|---|---|---|
| 1 | 一张级数牌 | 那门花色 |
| 2 | 一对级数牌 | 那门花色 |
| 3 | 一对小王 → 反成无主 | `null` |
| 4 | 一对大王 → 反成无主 | `null` |

规则(全在 `RULES.md`,这里只列你必须自己判的):

* 你返回的组合**必须是你手上真拿得出来的** —— 拿不出来记一次违规(不罚分,当作没亮)
* 压过别人要 `strength` 更大,而且**不能反自己**
* **加固**(自己亮的单张升成一对)是唯一例外:必须是你自己亮的、必须是单张、必须还没人用王对反过
* **无主局**(`dealerKnown === false`)里你的级数是 `view.trumpRank`,已经按你队的级数算好了

### `onRebel(view) → boolean`

定主之后,如果你手牌太差(分 ≤ 15,或主牌 ≤ 3 张),裁判会问你要不要掀桌重发。只有**庄家的对方队**会被问,从庄家下家起问一圈,第一个说 `true` 的生效。

重发之后按无庄局处理(双方重新抢庄)。同一局最多连重发 3 次,之后直接开打。

### `discard(view) → Card[8]`

你是庄家,手上 33 张(25 + 底牌 8),扣掉 8 张。

必须**恰好 8 张、全在手上、无重复**。不合格记一次违规并**罚 40 分**,裁判替你扣。

扣底的分会翻倍算给闲家 —— 倍数是 `2 × 最后一墩每人的张数`,所以末墩被拖拉机拿走就是 **×8**。

### `lead(view) → Card[]`

领出。返回 `Card[]` 或 `{cards: Card[]}` 都行。

**甩牌**(一次出同门多组)要赌没人吃得下你最小的那一组。赌输了裁判罚你只出最小的那一组 —— 这**不算违规、不罚分**,甩牌本来就是赌博。

### `follow(view, plays) → Card[]`

跟牌。`plays` 是本墩已出的几手,`plays[0]` 是领出。

跟牌规矩(完整形式在 `RULES.md` §S3):

1. **张数**必须等于领出的张数
2. **有则必跟**:本门有几张就得出几张
3. **对子也得跟**:领出有 `need` 对,你本门有 `have` 对,就得出 `min(need, have)` 对
4. 领出是**拖拉机**时,手上有同长或更长(可拆)的拖拉机必须跟;只有更短的也必须跟出短的

跟错了裁判替你出一手合法的,**按替出的张数 × 5 分罚**。

## 4. 罚分

口径就一句话:**裁判替你出了几张牌,就罚几张 × 5 分。**

| 情况 | 罚 |
|---|---|
| 跟牌不合法 / 出了手里没有的牌 / 抛异常 | 那一手的张数 × 5 |
| 扣底张数不对 | 8 × 5 = **40** |
| 亮主返回了拿不出来的组合 | **0**(当作没亮) |
| 亮主压不过现在的 | **0**(判断失误,连违规都不算) |
| 甩牌被吃 | **0**(强制出最小的一组) |

罚的分**记到对方队头上**:

* 你是庄家方犯规 → 罚分加进闲家的得分
* 你是闲家犯规 → 从闲家的得分里扣

每局的罚分效果封顶在"**这一局输光**" —— 罚到闲家得分归零(或满)就不再往下罚了。

**代码和策略一样值钱。** 一局牌面 200 分、80 分上台。偶尔一手 bug(30 张里错 1 张)罚 5 分,可以忽略;但规则理解有**系统性错误**(比如拖拉机跟牌搞反,三成跟牌都错)一局就罚掉 40 分以上,足够输掉这一局。

## 5. 你需要自己实现什么

裁判**什么工具都不借给你**。照 `RULES.md` 写,至少要有这些:

| 你要能回答 | `RULES.md` 里的位置 |
|---|---|
| 这张牌实际算哪门?(王、级数牌、主花色都算主) | §S3 `effSuit` |
| 主牌内部谁大谁小? | §S3 `ordIdx` |
| 这一把牌是单张 / 对子 / 拖拉机 / 甩牌? | §S3 `decompose` `classify` |
| 这么跟合不合法? | §S3 `isLegalFollow` |
| 这墩谁赢、多少分? | §S3 `resolveTrick` |
| 这一局结算成什么、升几级? | §S3 `scoreRound` `advanceMatch` |

**§S3 有全部八个判定的伪码,§S5 有约 60 条自测向量。** 跑通那张表,你的引擎就和裁判的一致 —— 这是你能在提交之前自查的唯一手段,**务必跑通它**。

`RULES.md` 是**唯一权威**。如果裁判的实现和它不一致,那是我们的 bug:公开修、受影响的对局重跑。你不需要去猜我们的实现细节。

## 6. 赛制

**打级,考全套。** 一场从 2 打到 A,谁先打过 A 谁赢,平均 30 局左右。亮主、造反、扣底、出牌全部由你决定。

**联赛:所有选手两两都要对过局。** 我们会安插一个基准选手一起打,它和你们一样受同样的规则约束。

只对一个固定对手打,优化目标会歪成"专治这一个" —— 两两对过局之后,靠某个对手的特定弱点吃分的选手在别人身上讨不到便宜。

### 每一对怎么打

同一批牌**两边各打一遍**:第一场你坐东西家,第二场你坐南北家,**牌完全一样**。这样运气就抵消了 —— 同一手好牌两边都摸到过,剩下的差距才是真本事。

(打级里这只能消掉每场第一局的牌运:庄家轮换按输赢分叉,之后两场的牌序列必然发散。这是打级赛制的固有代价。)

### 看哪些数

| 口径 | 是什么 |
|---|---|
| **胜场** | 谁先打过 A —— 打级的定义 |
| **净胜级/场** | 打完时你比对手高几级。三个口径里**最灵敏** |
| **每局净分** | 把整场拆回单局 |
| **罚分/局** | 你的代码错了多少 |

最终名次综合这几项,不是单看一个数。

## 7. 怎么开发

**没有现成的对局环境给你,自己搭。** 这是比赛的一部分。

大致路线:

1. **先照 `RULES.md` §S3 写引擎**,用 §S5 的自测向量验到全过。这一步做扎实,后面每一步都省事;做不扎实,罚分会一路跟着你。
2. **搭一个自己的对局循环**:发牌 → 亮主 → 扣底 → 25 墩 → 结算 → 升级。`RULES.md` §S2 有一局的完整时序。
3. **让你的 AI 自己跟自己打**,或者写几个不同版本互相打,从中找问题。
4. **量的时候当心方差。** 打牌的运气极大,跑 20 局看出来的"改进"多半是噪声。同一批牌交换阵营再打一遍,把两场的结果合起来看 —— 这一招能把牌运消掉一大半。

提交之前自查两条:

* §S5 的自测向量全过
* 自己跑几场完整对局,确认不会抛异常

## 8. 容易写错的十个地方

1. `history` 是扁平的,**每 4 个一墩**,一墩恒 4 手不管每手几张。
2. 王的 `suit` 是 `'X'` **不是** `null`;`trump.suit === null` 才是无主局。
3. 算主牌的时候别只算主花色 —— **王和两门副花色的级数牌也是主**。
4. 主花色散牌的大小**与级数无关**:要把级数那一档从 2..14 里挖掉之后重新排。
5. 两副牌,同一张牌有两张,`rank` 和 `suit` 都一样。**判重必须用 `id`**。
6. 拖拉机要**主牌序号差恰好为 1** 才连得上,不是 `rank` 差 1。
7. 配对是按 `(suit, rank)` 配的 —— 主花色里 `♠A♠A` 和副级对子序号相邻但花色不同,连不连得上看规则书。
8. 平手(结构相同、大小相同)是**先出者赢**。
9. 抠底倍数是 `2 × 最后一墩每人的张数`,**不是固定 2 倍**。
10. `deal` 阶段的 `view.hand` **只有已经发到的牌**,不是 25 张。别在那里假设手牌是完整的。
