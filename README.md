## 1. 你要交什么

**一个目录**,入口是 `index.js`。里面想放几个文件都行 —— 你要装下自己写的规则引擎,一个文件多半塞不下。

```
my-ai/
  index.js        ← 入口,必须有
  engine.js       ← 你自己照 RULES.md 写的规则实现
  strategy.js     ← 随你怎么拆
```

`index.js` 导出一个**不收参数**的工厂:

```js
module.exports = () => ({
  name: '你的名字',
  onDeal(view)        { return null; },
  onRebel(view)       { return false; },
  discard(view)       { return view.hand.slice(0, 8); },
  lead(view)          { return [view.hand[0]]; },
  follow(view, plays) { return view.hand.slice(0, plays[0].cards.length); },
});
```

复制 [`example/`](example/) 开始改。

### 怎么交

1. **Fork 这个 repo**
2. 把你的目录放进 `submissions/<你的名字>/`,例如 `submissions/zhang-san/index.js`
   * 目录名用英文小写和连字符,一个人只交一个
   * 别改 `submissions/` 以外的任何文件 —— 改了的 PR 会被退回
3. **提 PR** 过来

截止之后我们把所有提交拉下来,在同一台机器、同一批牌上跑联赛。

**交之前自查两条**(见 [§7](#7-怎么开发)):`RULES.md` §S5 的自测向量全过;
自己跑几场完整对局,确认不抛异常。

### 你的代码跑在什么环境里

一间**只有 JS 内建的空屋**:

| 有 | 没有 |
|---|---|
| `Object` `Array` `Math` `JSON` `Map` `Set` `Promise`… | `require('fs')` / `require('http')` / 任何 node 内置模块 |
| `require('./别的文件.js')`(你自己目录里的) | `process`、环境变量、命令行参数 |
| `console.log`(会带上你的名字前缀) | npm 依赖 —— **一个都不能用** |

纯 JavaScript,不能读写文件,不能联网。想预计算一张表就写进代码里。

**没有随机源也是有意的**:`Math.random` 在你屋里可用,但用了会让你的成绩不可复现、申诉时无法回放。要随机就自己带一个种子发生器。

### 时间

每次调用都计时。裁判不会中途打断你(同步调用打断不了)。两条门槛,都按 **CPU 时间**算:

| | 门槛 | 基准选手实测 |
|---|---|---|
| **一整场里你这一方的总用时** | ≤ **20 秒** | **6.8 秒** |
| **任何单次决策** | ≤ **2 秒** | 最慢的一次 0.21 秒 |

第一条是主要门槛(20 秒 ≈ 基准选手的 3 倍),第二条只是防某一手卡死。

**基准选手的数字就在上面 —— 不用猜。** 它在参考机器上(Node 22,单核)每场约 6.8 秒 CPU:
一场约 6000 次决策,其中六成是发牌阶段的 `onDeal`(中位数 5 µs,可以忽略),
时间几乎全在 `lead`(中位数 3.7 ms、p95 72 ms)和 `follow`(中位数 0.8 ms)上。
关掉它的收官搜索会快到 1.6 秒 —— 但联赛里是**开着**跑的,所以门槛按 6.8 秒定。

参考:第一届两份提交实测每场 **0.23 秒**和 **0.07 秒**,都在门槛的 1/100 以下。
这条门槛是用来挡住失控的实现的,**不是让你为它做优化**。
上一届有人为了对表这条规则花掉了大半轮时间做纯提速,而那些工作对棋力零贡献 ——
先把牌打好,时间不够了再来优化。

**怎么量(三条都写死,免得两边量出不同的数):**

1. **CPU 时间,不是墙钟。** 用 `process.cpuUsage()`。机器有争用时墙钟会把比值整个推高,
   而且同一份代码前后能量出 2.8× 和 3.9× 两个数 —— 不可复现的口径不能当门槛。
2. **整场总和,不是每次调用的平均。** 平均值会被占六成的 `onDeal` 稀释成一个没意义的小数。
3. **丢掉前两场再开始计。** JIT 没热起来之前,重的实现会被系统性高估。

## 2. `view` —— 你能看到的一切

这是唯一的信息入口。**没有别的口子**:看不到别人的手牌,看不到还没发的牌,看不到底牌(除非你是庄家)。

`view` 和里面每一张牌都是**冻结**的。你改不动 —— 想改就先自己拷一份。

### 牌长什么样

```js
{ suit: 'S'|'H'|'D'|'C'|'X', rank: 2..16, id: 0..107 }
```

* `S`♠ `H`♥ `D`♦ `C`♣,`X` 是王
* `rank`:数字牌 2–10,`11`=J `12`=Q `13`=K `14`=A;王的 `rank` 是 `15`(小王)`16`(大王)
* **两副牌 108 张**,所以每种牌都有两张,花色点数完全相同 —— **`id` 才是唯一标识**,判重、比较、返回都用 `id`

裁判**只认 `id`**。你返回什么形状的对象都无所谓,它按 `id` 去自己那份手牌里取真牌。所以伪造牌面既无害也无用。

### 每个阶段都有的字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `phase` | `'deal'｜'rebel'｜'discard'｜'lead'｜'follow'` | 这次问的是哪件事 |
| `seat` | `0..3` | 你的座位。**0=南 1=东 2=北 3=西**,`(seat+1)%4` 是你下家(逆时针) |
| `myTeam` | `0｜1` | `seat % 2`。你的队友坐 `(seat+2)%4` |
| `hand` | `Card[]` | **你自己**的手牌。`deal` 阶段只有已经发到你手上的那几张 |
| `trumpRank` | `2..14` | 本局打几 |
| `trump` | `{suit, rank}｜null` | 主。`suit === null` 是**无主局**。`deal` 阶段恒为 `null` |
| `declSeat` | `0..3｜-1` | ⚠️ **是庄家,不是亮主的那一家。** 名字有误导,读作 `dealerSeat`。`deal` 阶段恒为 `-1` |
| `curDecl` | `{seat,suit,strength}｜null` | 当前谁亮了什么 |
| `rebelHappened` | `boolean` | 已经有人用王对反过 —— 之后不能再加固 |
| `dealerKnown` | `boolean` | `false` = 无庄局,各家按自己队的级数抢亮,最终亮主者坐庄 |
| `dealer` | `0..3｜-1` | **发牌前就定好的**庄家(无庄局为 `-1`)。和 `declSeat` 的区别见下 |
| `firstTaker` | `0..3` | 先拿牌的那家 |
| `levels` | `[l0, l1]` | 两队级数。`levels[view.myTeam]` 是你队打到几 |
| `played` | `[p0, p1]` | 各队**坐庄守住过**的最高级数,没有则 `-1`。必打关卡要用 |
| `gates` | `number[]` | 必打关卡,默认 `[2,5,10,13]` |
| `round` | `number` | 整场的第几局(0 起) |
| `kittySize` | `8` | 底牌张数 |
| `history` | `Play[]` | 已出的牌,见下 |
| `buriedKnown` | `Card[]` | 底牌 —— **只有庄家非空**,别人恒为 `[]` |

> **`dealer` 和 `declSeat` 是两个不同的东西,都叫「庄家」。**
> `dealer` 是**发牌之前**就定好的庄家(无庄局里没有,为 `-1`);
> `declSeat` 是**定完主之后**的庄家。庄定局里两者相同;无庄局里 `dealer = -1`,
> 而 `declSeat` 要等亮主结束才定下来(最终亮主者坐庄,无人亮主则先拿牌者坐庄)。
>
> 在庄定局里,**亮主的人和庄家常常不是同一个人** —— 闲家反主只改主色,不换庄。
> 所以 `declSeat` 这个名字读起来像「亮主者」,但它不是。想知道谁亮的看 `curDecl.seat`。

分阶段还会多给:

| 阶段 | 多给 |
|---|---|
| `rebel` | `rebelReason: {pts, nT, byPts, byTrump}` —— 你凭什么够格造反 |
| `lead` / `follow` | `trickNo` —— 第几墩(0 起) |

### `history` —— 最容易写错的地方

它是**扁平**的 `{seat, cards}` 数组,不是按墩分好的。

* **每连续 4 个元素是一墩**,其中第一个是那墩的领出
* 一手可能是多张(对子、拖拉机、甩牌),但**一墩永远是 4 手**,不管每手几张
* `history.length % 4` 就是本墩已经出了几手
* 你在 `follow` 里拿到的 `history` **已经包含**本墩前面几家出的牌

按墩切开:

```js
const tricks = [];
for (let i = 0; i + 4 <= view.history.length; i += 4)
  tricks.push(view.history.slice(i, i + 4));
```

## 3. 五个方法

### `onDeal(view) → {suit, strength} | null`

发牌是**逐张**的:100 张牌一张一张发出去,**每发出一张就问收到它的那一家一次**。
所以一局全桌一共问 100 次,**摊到你头上是约 25 次**(每收到一张牌被问一次)。

发完之后还会绕圈再问,直到一整圈没人动作(上限 4 圈),所以「最后一张到手才够格亮」也来得及。
**收尾这几圈里 `view.hand` 已经是完整的 25 张了** —— 只有发牌途中那 25 次才是残缺的。

返回 `null` = 这次不亮。返回一个选项 = 现在就亮。

`strength` 的含义:

| 值 | 什么 | `suit` |
|---|---|---|
| 1 | 一张级数牌 | 那门花色 |
| 2 | 一对级数牌 | 那门花色 |
| 3 | 一对小王 → 反成无主 | `null` |
| 4 | 一对大王 → 反成无主 | `null` |

规则(全在 `RULES.md`,这里只列你必须自己判的):

* 你返回的组合**必须是你手上真拿得出来的** —— 拿不出来记一次违规(不罚分,当作没亮)
* 压过别人要 `strength` 更大,而且**不能反自己**
* **加固**(自己亮的单张升成一对)是唯一例外:必须是你自己亮的、必须是单张、必须还没人用王对反过
* **无庄局**(`dealerKnown === false`)里你的级数是 `view.trumpRank`,已经按你队的级数算好了
  —— 注意是**无庄**局(没有预定庄家、要抢庄),不是**无主**局(`trump.suit === null`,
  没人亮主或被王对反成无主)。两个完全不同的概念,别看混

### `onRebel(view) → boolean`

定主之后,如果你手牌太差(分 ≤ 15,或主牌 ≤ 3 张),裁判会问你要不要掀桌重发。

**谁会被问:只有庄家的对方队,而且只有真正够格的那几家。** 从庄家下家起按座位问一圈,
第一个说 `true` 的生效。不够格的家**根本不会被调用** —— 所以你在 `onRebel` 里
不用再自己判一次资格,被问到就说明你够格(`view.rebelReason` 告诉你凭哪一条)。

这条规则在游戏本体里是**可关的可选规则、默认关**,但**比赛裁判是开着跑的**
(「完全造反」模式)。别因为规则书写着「默认关」就不实现它。

重发之后按无庄局处理(双方重新抢庄)。同一局最多连重发 3 次,之后直接开打。

### `discard(view) → Card[8]`

你是庄家,手上 33 张(25 + 底牌 8),扣掉 8 张。

必须**恰好 8 张、全在手上、无重复**。不合格记一次违规并**罚 40 分**,裁判替你扣。

扣底的分会翻倍算给闲家 —— 倍数是 `2 × 最后一墩每人的张数`,所以末墩被拖拉机拿走就是 **×8**。

### `lead(view) → Card[]`

领出。返回 `Card[]` 或 `{cards: Card[]}` 都行。

**甩牌**(一次出同门多组)要赌没人吃得下你最小的那一组。赌输了裁判罚你只出最小的那一组
(「最小」按 `top` 序号算,**可能是一对而不是单张**)—— 这**不算违规、不罚分**,甩牌本来就是赌博。

**甩牌成立 ≠ 这一墩收得下来。** 成不成立只看**本门**有没有人压得过;
而这一墩谁收是**跨门**比的 —— 断门的人用主牌照样敲得掉。这两件事用的是两套口径,
把「甩牌成立」当成「这墩稳了」是策略层最常见的错。

### `follow(view, plays) → Card[]`

跟牌。`plays` 是本墩已出的几手,`plays[0]` 是领出。
和 `lead` 一样,返回 `Card[]` 或 `{cards: Card[]}` 都行(裁判两种都接)。

跟牌规矩(完整形式在 `RULES.md` §S3):

1. **张数**必须等于领出的张数
2. **有则必跟**:本门有几张就得出几张
3. **对子也得跟**:领出有 `need` 对,你本门有 `have` 对,就得出 `min(need, have)` 对
4. 领出是**拖拉机**时,手上有同长或更长(可拆)的拖拉机必须跟;只有更短的也必须跟出短的

跟错了裁判替你出一手合法的,**按替出的张数 × 5 分罚**。

## 4. 罚分

口径就一句话:**裁判替你出了几张牌,就罚几张 × 5 分。**

| 情况 | 罚 |
|---|---|
| 跟牌不合法 / 出了手里没有的牌 / 返回的形状不对 | 裁判替出那一手的张数 × 5 |
| 扣底张数不对 | 8 × 5 = **40** |
| 亮主返回了拿不出来的组合 | **0**(当作没亮) |
| 亮主压不过现在的 | **0**(判断失误,连违规都不算) |

**甩牌被吃不在这张表里** —— 它是规则内的合法赌博,不是违规:甩不成立就强制出
`top` 最小的那一组(可能是一对,不是张数最少的),**不罚分、不记违规**。
放进罚分表会让人以为甩牌有风险成本,其实它是个免费期权。

#### 你的方法抛异常了怎么办

裁判**接住,不让它穿透**,然后按这个方法该有的兜底走:

| 抛异常的方法 | 裁判怎么办 | 罚 |
|---|---|---|
| `onDeal` | 当作这一次没亮主 | **0** |
| `onRebel` | 当作不造反 | **0** |
| `discard` | 用裁判自己的扣底 | **40** |
| `lead` | 用裁判自己的领出 | 替出那一手的张数 × 5 |
| `follow` | 用裁判自己的跟牌 | 替出那一手的张数 × 5 |

抛异常和「返回了一手非法牌」**罚得一样**,只是违规记录里的名目不同
(`lead:抛异常` / `lead:不合法`)。整场不作废、不判负。

所以**不要在最外层无差别 `try/catch` 兜一手合法牌**。那样裁判看到的是合法着法、
不记违规、不罚分,而你的策略层其实每一手都在抛 —— 成绩单上完全看不出来。
上一届真有人踩了这个坑:自查零违规、全绿,棋力却掉了 0.57 级/局。
要兜也兜在能被你自己看见的地方。

#### 裁判替出的具体是什么牌

规则书没规定这个(替法不影响罚分),但既然会影响后续牌局,把我们的实现写出来:
扣底 → 裁判自己的扣底策略;领出 → 裁判自己的领出;跟牌 → 满足一切义务的最小合法跟。
**你不需要猜这个,也不需要对齐它** —— 它只在你已经出错之后才发生。

罚的分**记到对方队头上**:

* 你是庄家方犯规 → 罚分加进闲家的得分
* 你是闲家犯规 → 从闲家的得分里扣

每局的罚分效果封顶在「**这一局输光**」,具体是:

> 把**闲家的墩内得分**(加减完双方罚分之后)夹回 **[0, 200]**,再按这个数去算抠底翻倍。

所以最终的闲家总分**可以超过 200** —— 抠底是在夹完之后乘上去的(末墩拖拉机就是 ×8)。
夹的是墩内得分,不是最终总分。

**代码和策略一样值钱。** 一局牌面 200 分、80 分上台。偶尔一手 bug(30 张里错 1 张)罚 5 分,可以忽略;但规则理解有**系统性错误**(比如拖拉机跟牌搞反,三成跟牌都错)一局就罚掉 40 分以上,足够输掉这一局。

## 5. 你需要自己实现什么

裁判**什么工具都不借给你**。照 `RULES.md` 写,至少要有这些:

| 你要能回答 | `RULES.md` 里的位置 |
|---|---|
| 这张牌实际算哪门?(王、级数牌、主花色都算主) | §S3 `effSuit` |
| 主牌内部谁大谁小? | §S3 `ordIdx` |
| 这一把牌是单张 / 对子 / 拖拉机 / 甩牌? | §S3 `decompose` `classify` |
| 这么跟合不合法? | §S3 `isLegalFollow` |
| 这墩谁赢、多少分? | §S3 `resolveTrick` |
| 这一局结算成什么、升几级? | §S3 `scoreRound` `advanceMatch` |

**§S3 有全部八个判定的伪码,§S5 有约 60 条自测向量。** 跑通那张表,你的引擎就和裁判的一致 —— 这是你能在提交之前自查的唯一手段,**务必跑通它**。

`RULES.md` 是**唯一权威**。如果裁判的实现和它不一致,那是我们的 bug:公开修、受影响的对局重跑。你不需要去猜我们的实现细节。

## 6. 赛制

**打级,考全套。** 一场从 2 打到 A,谁先打过 A 谁赢,平均 30 局左右。亮主、造反、扣底、出牌全部由你决定。

**联赛:所有选手两两都要对过局。** 我们会安插一个基准选手一起打,它和你们一样受同样的规则约束。

只对一个固定对手打,优化目标会歪成"专治这一个" —— 两两对过局之后,靠某个对手的特定弱点吃分的选手在别人身上讨不到便宜。

### 每一对怎么打

同一批牌**两边各打一遍**:第一场你坐东西家,第二场你坐南北家,**牌完全一样**。这样运气就抵消了 —— 同一手好牌两边都摸到过,剩下的差距才是真本事。

(打级里这只能消掉每场第一局的牌运:庄家轮换按输赢分叉,之后两场的牌序列必然发散。这是打级赛制的固有代价。)

### 看哪些数

| 口径 | 是什么 |
|---|---|
| **胜场** | 谁先打过 A —— 打级的定义 |
| **净胜级/场** | 打完时你比对手高几级。三个口径里**最灵敏** |
| **每局净分** | 把整场拆回单局 |
| **罚分/局** | 你的代码错了多少 |

最终名次综合这几项,不是单看一个数。

## 7. 怎么开发

**没有现成的对局环境给你,自己搭。** 这是比赛的一部分。

大致路线:

1. **先照 `RULES.md` §S3 写引擎**,用 §S5 的自测向量验到全过。这一步做扎实,后面每一步都省事;做不扎实,罚分会一路跟着你。
2. **搭一个自己的对局循环**:发牌 → 亮主 → 扣底 → 25 墩 → 结算 → 升级。`RULES.md` §S2 有一局的完整时序。
3. **让你的 AI 自己跟自己打**,或者写几个不同版本互相打,从中找问题。
4. **量的时候当心方差。** 打牌的运气极大,跑 20 局看出来的"改进"多半是噪声。同一批牌交换阵营再打一遍,把两场的结果合起来看 —— 这一招能把牌运消掉一大半。

提交之前自查两条:

* §S5 的自测向量全过
* 自己跑几场完整对局,确认不会抛异常

## 8. 容易写错的十四个地方

1. `history` 是扁平的,**每 4 个一墩**,一墩恒 4 手不管每手几张。
2. 王的 `suit` 是 `'X'` **不是** `null`;`trump.suit === null` 才是无主局。
3. 算主牌的时候别只算主花色 —— **王和两门副花色的级数牌也是主**。
4. 主花色散牌的大小**与级数无关**:要把级数那一档从 2..14 里挖掉之后重新排。
5. 两副牌,同一张牌有两张,`rank` 和 `suit` 都一样。**判重必须用 `id`**。
6. 拖拉机要**主牌序号差恰好为 1** 才连得上,不是 `rank` 差 1。
7. 配对是按 `(suit, rank)` 配的 —— 主花色里 `♠A♠A` 和副级对子序号相邻但花色不同,连不连得上看规则书。
8. 平手(结构相同、大小相同)是**先出者赢**。
9. 抠底倍数是 `2 × 最后一墩每人的张数`,**不是固定 2 倍**。
10. `deal` 阶段的 `view.hand` **只有已经发到的牌**,不是 25 张。别在那里假设手牌是完整的。
    (但发完之后**绕圈补问**那几次,手牌已经是完整的 25 张了。)
11. **一局不是固定 25 墩。** 循环条件是「还有人手里有牌」—— 只要有人领出对子或拖拉机,
    一墩就消耗每人两张以上,墩数必然少于 25(实测中位数 18,恰好 25 墩的占 0.007%)。
    写成 `for (t = 0; t < 25; t++)` 会在手牌打空之后继续取牌。
    **上一届两份提交都栽在这一条上**,而且都是跑崩了才发现。
12. **甩牌成立 ≠ 这一墩收得下来**(见 `lead`)。
13. **兜底本身不能抛异常。** 它是最后一道防线,它抛了就没有下一道了 ——
    三处兜底都要写在 `try` **里面**,并且只做最小假设。
14. **别在最外层无差别 `try/catch` 兜一手合法牌**(见 §4)。裁判看到的是合法着法,
    不记违规、不罚分,你的自查全绿 —— 而崩溃是完全隐形的。

## 9. 这一版改了什么

2026-09-05。第一届两位参赛者各交了一份 `NOTES.md`,把规则书和这份手册里说不清的地方
一条条列了出来。照着规则书写引擎的人,比写规则书的人更看得清它哪里有洞。这一版:

  不可知 —— 一条硬性淘汰条件变成了没法自查的东西。上一届有人为它花掉大半轮时间做纯提速,
  对棋力零贡献。现在基准选手的实测值、计时口径、怎么归一、预热怎么算,全部写死。
* **抛异常怎么处理**(§4)。原来一个字没写,只能猜。现在按方法逐条列出来。
* **罚分封顶的「满」是多少**(§4)。原来写「归零(或满)」,「满」没有数字。
* **`declSeat` / `dealer` 的区别**(§2)。两个字段都叫「庄家」,而 `declSeat` 的名字
  读起来像「亮主者」—— 它不是。
* **`onDeal` 一局问几次**(§3)。「一局 100 次」是全桌的总数,摊到你头上约 25 次。
* **`onRebel` 只问够格的家**(§3);以及这条规则在比赛里是**开着**的。
* **`follow` 的返回值形状**(§3)和 `lead` 一样,两种都接。
* **甩牌搬出罚分表**(§4)—— 它是规则内的赌博,不是违规,放在罚分表里反而误导。
* §8 从十条加到十四条。
