# NOTES —— 照 RULES.md 实现时遇到的洞

(边做边记,最后整理)

## 1. §S2 说「打 25 墩」,但一局的墩数不是 25

§S2 第 ⑥ 步:「打 25 墩:庄家领出;每墩四家各出一手」。
但只要有人领出对子或拖拉机,一墩就会消耗每人 2 张以上,**总墩数必然少于 25**。
我第一版照字面写了 `for (t = 0; t < 25; t++)`,第 21 墩就崩了(手牌已空)。

正确的终止条件是「手牌出完」。规则书没有任何一处写这件事,
§S5 也没有一条向量覆盖「一局有几墩」。**建议 §S2 改成「打到手牌出完(最多 25 墩)」。**

顺带影响 G 节:「最后一墩」指的是**实际打完的最后一墩**,不是第 25 墩。

## 2. 完全造反默认到底是开还是关

- `RULES.md` §I 参数表:「完全造反 | 默认**关** | off / 仅重新发牌 / 完全造反」
- `README.md` §3 `onRebel`:「定主之后,如果你手牌太差…**裁判会问你要不要掀桌重发**」,
  并且明确写了「重发之后按无庄局处理」「同一局最多连重发 3 次」

两者矛盾。README 描述的是裁判实际会调用的接口,所以我按**开、且是「完全造反」模式**实现,
并让 `onRebel` 的激进程度成为一个可调开关。
如果裁判其实是关的,我的 `onRebel` 返回什么都不影响结果,损失只是白写。

## 3. `decompose` 的扫描是贪心的,会漏掉更长的拖拉机

§S3 ③ 写的是「pairs 按 ordIdx 升序排;扫描 pairs:相邻两对若 ordIdx 差恰为 1 → 接进当前 run」。
遇到**同序号的两对**时会出问题。主♠打2,手上 ♠A♠A(11) + ♥2♥2(12) + ♦2♦2(12) + ♠2♠2(13):
排序后是 11,12,12,13,贪心扫描切成 [11,12] 和 [12,13] 两条二连,
但实际上 11→12→13 能连成**三连对**。

我**照伪码字面实现**(两条二连),因为规则书说「引擎与伪码逐行对应」。
但这意味着同样一手牌,「是不是拖拉机」取决于扫描顺序而不是牌本身,
`isLegalFollow` 的 `m`(最长拖拉机)和 `canBeatComp` 都会跟着受影响。
§S5 没有一条向量覆盖「同序号对子 + 相邻对子」的组合。**这是规则书的洞。**

## 4. `rebelHappened` 的准确含义

README 只写「已经有人用王对反过 —— 之后不能再加固」。
是「有人**成功**用王对反了」还是「有人**尝试**过」?我按**成功**实现
(`declarationOf` 返回 strength≥3 且通过了 `declAllowed`)。
§S5 的向量只测「已发生造反 → 不可加固」,没有区分这两种读法。

## 5. README 把「无庄局」写成了「无主局」

README §3 `onDeal` 最后一条:「**无主局**(`dealerKnown === false`)里你的级数是 `view.trumpRank`」。
`dealerKnown === false` 是**无庄局**(没有预定庄家、要抢庄),
「无主局」是 `trump.suit === null`(王对造反成功或无人亮主)。两个完全不同的概念,
同一份 README 的 §8 第 2 条又正确地区分了它们。容易读错。

## 6. 罚分封顶「罚到闲家得分归零(或满)」中的「满」是多少

README §4:「每局的罚分效果封顶在『这一局输光』—— 罚到闲家得分归零(或满)就不再往下罚了」。
「满」没给数字。牌面总分 200,但闲家最多也只能拿到牌面上的分 + 抠底翻倍(可以超过 200)。
我按 **[0, 200] 截断闲家的墩内得分**,再算抠底。这个选择对我的策略没有影响
(我不会故意犯规),但对裁判的实现是个歧义点。
