# NOTES.md —— zai-glm 第二赛季规则反馈与说明

## 0. 本提交是什么

以官方公开的基线 AI（`ChannonTian/80fen` 的 `index.html` v0.7.14 块①，Apache-2.0，
`contest/baseline.js` 头部明示「参赛者的起点：想改进而不是从零写的，直接 fork 这个文件」）
为基座 fork，在其上做独立改进。基座部分（引擎+AI 约 3600 行）原样保留；改进全部通过
`AIP.s2*` 开关实现并逐项配对测量（详见 PROGRESS.md），默认只打开测量为正的项。

## 1. 等价性验证方法（供复核）

fork 之后、改动之前，先做了两层「与陪练逐位等价」校准：

1. `node contest/league.js <fork目录> --seeds=6 --eg`：与陪练 6-6，配对级差 0.00±0.00、
   净分 0.00（同种子同牌同走法，完全确定性）。
2. 进程内 referee 配对对跑 6 seeds：全部指标恒 0。
改动全部走开关（默认关），开关全关时与基座逐位一致这条性质在每次晋级后重验。

## 2. 规则书的洞 / 反馈

本季引擎直接用官方实现，未再发现新的规则洞。第一赛季我报告过的两条
（「打 25 墩」在多张领出下不成立；对子义务的无可行解）在 09-05/09-06 版
已分别以「打到手牌出完」和存在性证明+构造顺序解决，本季实测无歧义。

两条小建议（非规则，属赛制透明度，供参考）：

1. **陪练版本对齐**：参赛者本地 fork 的基线版本（v0.7.14）与联赛当日陪练的 build
   可能不同。若赛季中陪练更新，参赛者无法提前知道。建议赛前公告陪练 build 版本号。
2. **计时口径**：联赛 5-worker 争用下的墙钟读数偏大（README 已写明）。建议公示
   「超时判定用的是哪个口径的数」，方便参赛者自留余量（我按无争用 ≤12s 自限）。
