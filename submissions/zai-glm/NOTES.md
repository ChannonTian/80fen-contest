# NOTES —— 规则书的洞、歧义与实现笔记

> 这份笔记照「哪里照规则书写不出来」来写。比强 AI 更有价值的是把洞如实写出来。

## 1. 无合法跟牌的局面(§S3 ⑤,最重要的一条)

**位置**:§S3 ⑤ `isLegalFollow` 伪码,对子义务那两行:

```
need = lead 里的对子数(pair=1,tractor=len,throw=各组件之和)
must = min(need, countPairsIn(suitInHand))
countPairsIn(chosenInSuit) >= must        否则 false
```

**问题**:`chosenInSuit` 最多 `k = min(领出张数, 本门张数)` 张,能容纳的对子数上限是 `⌊k/2⌋`,
但 `must` 没有这个封顶。于是存在**数学上无解**的局面:

- 领出甩牌 = 2 个单张(n=2),跟牌方本门有 ≥2 对 → must=2 > ⌊2/2⌋=1,任何 2 张牌都非法
- 领出甩牌 = 1 对 + 1 单(n=3),本门有 ≥2 对 → must=2 > 1
- 领出拖拉机长度 L,本门对子 ≥L 但 K 张塞不下 L 对的情形(更罕见)

**出现频率**:随机局面模糊测试 16801 例中 342 例(约 2%),多数由甩牌领出触发。

**我的理解与处理**:叙述部分(C 节)说义务「独立叠加」,并没有意图制造无解局面;
这更像伪码漏写封顶。我按「must 封顶到 ⌊k/2⌋」的宽松口径给最接近义务的一手,
本地裁判对这类局面不记违规不罚分。**若真实裁判严格照伪码实现,任何一方领出这种甩牌
都会让对方必然被罚(每张 5 分)——等于一个白捡的武器**;我没有利用它,因为裁判
「替你出一手合法的」这句话在此局面下没有定义,实际行为无法预测。

## 2. 一局的墩数不是 25(§2/§S2 叙述 vs 实现)

规则书说「打 25 墩」(每人 25 张、每墩每人 1 张的隐含假设)。但甩牌一墩每人出 >1 张,
**总墩数 = 25 只有在全 SINGLE 时成立**。实现时循环条件必须是「手牌出空」。
规则书没有明说这一点,S2 时序图里也没提。我在这里卡过一次(第 20 墩手牌已空)。

## 3. 无主局时「先拿牌的人坐庄」+ 级数归属(§F)

无庄局、无人亮主:按先拿牌者坐庄、打先拿牌那一队的级数 —— 这条在 F 节写了,
但 `view.trumpRank` 在 deal 阶段对每个座位分别等于**自己队**的级数,
两队级数不同时同一局里不同座位看到的 trumpRank 不一样。README 的字段表说
「无主局里你的级数是 view.trumpRank,已经按你队的级数算好了」,一致,没问题,
但初次实现容易以为全桌统一。**记下来供确认**。

## 4. 造反(重发)后的细节

- F 节:「完全造反 → 新的一局按无庄局处理」。重发之后**要不要重新切牌定先**?
  §S2 说重发「回到 ①」,① 就是切牌定先。我按重新切牌实现。
- README 说 onRebel 只有「庄家的对方队」会被问、从庄家下家起问一圈;
  RULES.md F 节说「任一家满足阈值可要求重发」。两处不一致。**我按 README 实现**
  (只问庄家对方队),因为接口文档对裁判行为的描述更具体。
- `rebelReason` 字段 README 写 `{pts, nT, byPts, byTrump}`,没说 pts/nT 是布尔还是数值。
  我当数值传(pts=手牌分,nT=主牌张数),byPts/byTrump 当布尔。**待确认**。

## 5. 罚分方向与封顶(README §4)

「罚的分记到对方队头上」+「效果封顶在这一局输光」:我实现为
庄家方犯规 → 加进闲家总分;闲家犯规 → 从闲家总分里扣,下限 0、上限 200。
「输光」的准确含义(归零还是归到上台线以下)规则书没细说,封顶只影响极端局面。

## 6. 甩牌失败「最小的那一组」

D 节:「最小 = 组件里 top 序号最低的那一组,可能是一对而不是单张」——写清楚了,赞。
但注意 `checkThrow` 判定**包括队友**且**只看本门**,与我最初直觉(排除队友)不同,
按规则书实现。这条不算洞,算容易错的地方。

## 7. view.curDecl 的字段

README 字段表写 `curDecl: {seat,suit,strength}｜null`。deal 阶段每次问询都会给当前值,
加固判断需要它 + 「我自己亮过什么」的记忆(AI 自己记)。规则书 F 节的加固条件
(本人、同花、单→对、任何造反之前)里「任何造反之前」由 `rebelHappened` 字段表达
——README 只说「已经有人用王对反过之后不能再加固」,与 F 节一致。无歧义,但
**「造反」一词同时指『王对反主』和『低分重发』两件事**,读 F 节时要小心。

## 8. 末墩的「无选择」性质(值得写进规则书的推论)

规则书没有明说,但从 §S3 ⑤ 可推出:**最后一墩的跟牌方没有任何选择** ——
手牌数 = 领出张数时,「有则必跟」把所有牌都锁死,唯一合法着法是全出。
推论:
- 「末墩抠底意识」对**跟牌方**是伪命题(我实现过一版,量到 0% 行为差后才想明白);
  抠底的争夺全在**领出方**(末墩领出对/拖拉机把倍数从 ×2 抬到 ×4/×6)和此前的守备
- 庄家扣底后「留大牌守底」的收益,只在还有选择余地的倒数第二、三墩体现

## 9. 甩牌失败的真实代价(策略观察,非规则洞)

D 节写「失败的甩牌只出最小的一组、不罚分」——字面上看像免费期权。
实测(配对跑分,n=1000):允许 1 个非锁顶组件混入甩牌 **-16.6σ**,允许 2 个 **-20.5σ**。
原因:被迫只出最小一组 ≠ 无损 —— 领出意图暴露、其余组件滞留手里、且最小组往往
直接被吃掉。**「被吃不罚分」和「被吃无代价」是两回事。**

## 10. 实现难度排序(主观)

1. **跟牌义务的叠加**(张数+对子+拖拉机三条同时满足,还要在候选生成器里
   生成出「含拖拉机段且补足对子数」的组合)—— 最难,义务之间有交互
2. 抠底倍数与末墩张数的联动(策略层面比引擎难)
3. 无主局的级数牌同级(平手先出胜)——引擎简单,策略上反直觉
4. advanceMatch 的 played 记账时机(先记账再升级)——一句话,但容易看漏

## 11. §S5 自测向量够不够用

- **不够**。以下错误它没抓出来,是我靠别的手段发现的:
  - `forceLegalFollow` 的义务叠加 bug(拖拉机义务满足后忘了对子义务)——
    S5 只测「什么非法」,不测「替出的一定合法」。我加了 2 万例模糊测试才抓到
  - 无合法跟牌的局面(上文 #1)——S5 没有任何奇数张甩牌的向量
  - advanceMatch 传不传 `played` 的语义差异(整场推进向量与关卡向量的隐性冲突,
    见 PROGRESS「教训」)——建议 S5 每条向量显式标注参数
- 建议补:奇数张甩牌的跟牌向量(至少标注预期行为);「替出着法必须合法」的属性测试;
  多局连打下 gates+played 交互的完整序列向量(现在只有单步)

## 12. README 有没有让我误解接口

- `follow(view, plays)` 的 `plays` 元素形状是 `{seat, cards}`,cards 是冻结的牌对象数组
  ——字段表没写,我读 example 推断的,对了
- `history` 扁平、含本墩已出手 —— README 写得很清楚
- 五个方法的返回值:`lead` 可返回 `{cards}` 包装,别的都没写包装,实测只有 lead 支持
- `view.hand` 在 deal 阶段逐张增长 —— 写清楚了,但**发完后的「绕圈再问」阶段**
  hand 是完整的 25 张,这个时点 README 只说「发完之后还会绕圈再问」,没说 hand 已满
