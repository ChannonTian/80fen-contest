# NOTES.md —— 规则书反馈 (照 RULES.md/README.md 实现时发现的洞与歧义)

按"照着写不出来/必须自己拍板"的程度排序。每条注明: 位置、我当时怎么理解、为什么。

## A. 规则书没说清、只能自己拍板的地方

1. **"打 25 墩" (RULES.md §S2⑥, README 多处)**: 每人 25 张, 但对子/拖拉机/甩牌墩每人不止出一张, 实际墩数 = 手牌打空为止, **只有全单张时才是 25 墩**。"25 墩"我理解为"25 张牌打完", 对局循环以手牌清空为终止条件。建议规则书改写成"打满 25 张(墩数随牌型变化)"。
2. **切牌后的 4 张切牌怎么处理 (§S2①)**: 没写。我按"放回牌堆重新洗牌"处理(否则 108 张不够发 100+8)。建议写明。
3. **发牌中 onDeal 的调用频率 (README §3)**: "每发到你手上一张就问你一次(一局 100 次)" 与 "每发到你手上一张" 有歧义: 是每人收到一张问一次(每局每家 ~25 次), 还是每发一张牌问所有人(每家 100 次)? 我按前者(收到牌才被问)。"一局 100 次" 疑为"发牌阶段全局共 100 次提问"。建议明确。
4. **亮主窗口的询问顺序 (§S2② "绕圈再问")**: 从谁开始绕没说。我按从先拿牌者开始、座位顺序。建议写明。
5. **造反询问对象**: README 说"只有庄家的对方队会被问", 且 view 里有 rebelReason —— 我理解为**只有够格(byPts/byTrump)的闲家**才会被问到, 从庄家下家起按座位顺序问, 第一个 true 生效。规则书未明确"够格的才问"还是"都问但只有够格的能 true"——对 AI 无差别(不够格返回 false 即可), 建议写死。
6. **罚分封顶"归零(或满)" (README §4)**: "满"是多少没写。我按 [0, 200] 截断(闲家得分不可能超过 200 的牌面总分)。建议写死"封顶在 0 和 200"。
7. **裁判替出时出什么牌**: 罚分口径只写"替出张数 × 5", 但替出的具体牌面没有规范(不同替法影响后续对局)。我的对局循环里: 扣底违规 → 扣分最少的 8 张; 领出违规 → 最小单张; 跟牌违规 → 满足一切义务的最小合法跟。**这部分是裁判自由裁量, 建议规则书至少写一句"替出方式由裁判实现决定, 不影响罚分"**, 让选手知道不必猜。
8. **被反之后能否再反回去 (§F)**: "不能反自己"只约束当前是自己亮的情形; 我的亮主被别家反了之后, 当前亮主是别家, 我再亮更强的 → 我按"允许"(canOverride 只拒绝"当前是自己的"时的非加固亮)。§S5 没有这条向量。建议补: "A 亮单, B 反对, A 再反王对 → ?"。
9. **§S5 整场推进行 vs 必打关卡行的 played 口径**: 整场推进行("队0到3")只有按伪码"不传 played = 只做第一层(不可跳级)"才成立; 必打关卡行("停在2")必须传 played。即两行用了不同的 advanceMatch 口径, 但表格里没标。建议在两行上分别标注。
10. **§S5 "拆散跟"向量**: "领出三连对、手中只有二连对 | 拆散跟 | partial关→合法, 开→非法" —— 若手中真的"只有"二连对(无其他对子), 第③条对子义务(必须跟 min(3,2)=2 对)会强制出这两个对子, 它们相邻, 天然还是拖拉机, partial 规则根本触发不了。该向量要成立, 手中必须还有**多余的对子**(如 55-66 + 88 + QQ, 拆散=出 55+88+QQ)。建议向量补一张手牌, 否则照着写引擎的选手会卡住。

## B. 最难实现的判定

1. **decompose 的拖拉机**: 级数牌从本门牌序挖掉 + 主牌里 11→12→13→14→15 的跨类相邻 + "同级不相邻"(差恰为 1)。最容易错: 打 2 时 ♥6♥6+♥8♥8 不是拖拉机(中间有 7)、主A对+正级牌对不相邻(隔副级牌档)。§S5 有向量, 够用。
2. **isLegalFollow 的三层叠加义务**: 张数 → 对子数 → 拖拉机(严格/部分两档), 以及"拆出子拖拉机必须是连续片段"。§S5 向量覆盖了主要分支, 但**甩牌领出(throw)的对子义务**没有向量(领出 throw 含拖拉机+单张时, 必须跟几个对子)——伪码写清了(need=各组件之和), 我按伪码实现, 建议补一条向量。
3. **resolveTrick 的结构多重集比较**: 甩牌领出时跟牌者必须"组件构成一模一样"才能比大小, 且"结构不同仍算分"。§S5 只有单张/对子墩向量, **没有甩牌墩向量**, 建议补: 领出 [对+单], 跟 [对+单] 同门较大者赢; 跟 [三单] 不参与比较但算分。
4. **checkThrow 的"任何组件被任何一家(含队友)压住即失败" + "强制出 top 最小的组件(可能是一对)"**: 伪码清楚, §S5 有两条向量(单+对的失败、全大成功), 但**没有"领出含拖拉机的甩牌"和"强制出的最小组件是一对"**的向量, 建议补。

## C. §S5 向量够不够用 / 有没有我写错了但它没抓出来的

- 我的实现过程里, §S5 没抓到、靠整场对局抓到的 bug:
  1. **跟牌义务征用对子时把"拖拉机"当成一个对子** —— 门内对子恰连成拖拉机时, 义务要求 2 对, 我只取了拖拉机的第一对。§S5 的跟牌向量里没有"义务对子恰好连成拖拉机"的情形。建议补。
  2. **垫牌单张填充只从"散单张"里选、没拆未被征用的对子** —— 领出单张、手牌只有对子(无散单)时必须拆对跟单。§S5 没有"跟单时被迫拆对"的向量。建议补。
  3. 切牌/底牌张数、多张墩的手牌清空时序 —— 这些属于对局循环, §S5 管不到(它是引擎级向量), 但规则书把"25 墩"写死让我在循环上踩了坑。
- 建议补充的向量(除上述外): 无主局的一墩胜负(有)、平手先出者胜(§S5 只提了规则, 无向量 —— 无主局异花级数牌对撞)、甩牌领出的跟牌义务、拖拉机甩牌判定。

## D. README 接口里让我误解/踩坑的地方

1. **"25 墩"与"history 每连续 4 个元素是一墩"**: 前半句让我把对局循环写死了 25 墩, 对子/甩牌墩多张时牌数对不上。正确理解: 一墩恒 4 手, 但总墩数 = 25 张打完为止(见 A1)。
2. **"view 和里面每一张牌都是冻结的"**: 我以为裁判给我的是副本; 实现上我按"AI 不得修改"处理。只要自己不改就行, 不必深究。
3. **"deal 阶段的 view.hand 只有已经发到的牌"**: 对, 但结合 A3 的提问频率, 容易以为发牌阶段每个玩家每张牌都被问一次。我按"收到自己的牌才被问"实现。
4. **"甩牌...赌输了裁判罚你只出最小的那一组"**: "最小"我一度按"张数最少"理解, 但规则书 D/S6 明确是 **top 序号最小**的组件(可能是一对)。建议 README 加一句"(top 序号最小, 可能是一对)"。
5. **"你的级数是 view.trumpRank, 已经按你队的级数算好了"**: 无庄局里各家用自己队的级数亮主 —— 我一开始误以为无庄局里亮主也用统一级数。规则书 §F 有写, README 这句其实够, 但容易漏。

## E. 其他实现决定 (对裁判透明, 无争议)

- 亮主选项验证: strength 1/2 要求同花色级数牌 1/2 张, 3/4 要求小/大王对且 suit=null; 拿不出 → 记违规不罚分、当作没亮。
- 亮主窗口 4 圈从先拿牌者起; 一圈无人动作提前结束。
- 完全造反后新局按无庄局处理并重新切牌(按 §S2① "首局/完全造反后 → 切牌")。
- 无庄局无人亮主: 无主局, 先拿牌者坐庄, 级数 = 先拿牌者队级数(按 §F)。
- 庄定局无人亮主: 无主局, 庄家不变(按 §F/S5)。
- 罚分: 庄家方犯规加给闲家得分, 闲家犯规从闲家得分扣, 封顶 [0,200](A6)。
- 对局循环: 墩数 = 手牌打空为止(A1)。
