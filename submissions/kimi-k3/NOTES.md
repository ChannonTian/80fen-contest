## 1. 规则书的洞与歧义

按严重程度排。每条:位置、两种解读、我选了哪种、为什么。

### H1. §S2 ⑥「打 25 墩」与多牌领出矛盾(最大的洞)

§S2 时序第 ⑥ 步写「打 25 墩:庄家领出;每墩四家各出一手」,第一部分 §3 ⑤ 同样写「打 25 墩」。

但 §S3 ⑤ 跟牌义务第 1 条要求**张数必须等于领出张数**,所以每墩四家各出 `leadSize` 张,四家的手牌永远**同步**消耗。一旦有人领出对子/拖拉机/甩牌,手牌会在不到 25 墩时同步耗尽 —— 25 墩只在全程单张领出时成立。实测我的 AI 自我对打平均每局 **15.2 墩**。

两种解读:(a) 打到手牌耗尽为止,「最后一墩」= 耗尽那一墩;(b) 末墩允许不满张的残墩 —— 但这直接违反 §S3 ⑤ 第 1 条,领出方连合法领出都构造不出来。

**我选了 (a)**:打到手牌耗尽。§G 抠底公式「2 × 最后一墩每人出的张数」在 (a) 下自然成立。建议规则书把 §S2 ⑥ 改成「打到手牌耗尽;25 是全单张领出时的墩数上限」。

### H2. §S5「整场推进」表与「必打关卡」表同输入矛盾

- 「整场推进」表:`[2,2]`,闲家上台升 1 级 → **队 0 到 3**。
- 「必打关卡」表:队 1 坐庄打 2,队 0 抢 150 分(= 上台升 1 级),`played=[-1,-1]` → **队 0 停在 2**,只换庄不升级。

同输入(levels=[2,2]、闲家上台升 1 级、gates 默认开、played=[-1,-1]),期望相反。唯一自洽的读法:**整场推进表是在关卡关闭下写的**。我的自测按这个读法实现(整场推进用 gates=[] 跑,必打关卡单独跑)全过。建议在整场推进表头注明「以下假定关卡关闭」。

### H3. 造反谁够格被问:RULES 与 README 不一致

- RULES §S2 ④:「(可选)低分/少主造反:**任一家**满足阈值可要求重发」。
- README `onRebel` 节:「只有**庄家的对方队**会被问,从庄家下家起问一圈,第一个说 `true` 的生效」。

两处不一致。我按 **README** 实现(它是接口文档,且与 F 节「完全造反」段的掀桌语义更搭)。对 AI 侧影响为零(我的策略是被问恒 yes,R9a 验证过这是对的),但裁判实现二选一会改变对局走向,值得定死。

### H4. 非法领出的罚则整体缺失

README §4 罚分表覆盖:跟牌不合法(那一手张数 ×5)、扣底张数不对(40)、亮主拿不出(0)、亮主压不过(0)、甩牌被吃(0)。**没有「领出非法」这一行** —— 领出混门牌、领出手上没有的牌,罚不罚、罚几张、替出什么,两处文档都没写。

我猜的口径:**罚 5 × 尝试张数,裁判替出当前手牌里最小的单张**(与跟牌罚则的量纲一致;替出单张保证 classify 必成立、时序能继续)。若裁判实际是「罚 0 只替出」或「罚 5×1」,对纪律性 AI(从不非法领出)无影响,但联赛里别人出错时会影响分差。

### H5. 罚分与抠底的结算顺序、「满」的定义

README §4:「罚的分记到对方队头上」「罚分效果封顶在'这一局输光' —— 罚到闲家得分归零(**或满**)就不再往下罚了」。「满」是多少没写(200?200+抠底?),罚分与抠底奖金谁先算也没写。顺序不同结果不同(罚分能不能吃掉抠底进账)。

我猜的口径:`闲家总分 = 墩分 + (抠底 ? 底分×2×末墩张数 : 0) + 庄家方罚分 − 闲家方罚分`,最后整体 clamp 到 **[0, 200]**(即罚分可以吃抠底,「满」= 200)。

### H6. 切牌完全相同的 tiebreak 缺失

§S2 ① / §S4:切牌「比自然大小(A 最大、2 最小,王比 A 还大),同点数比花色 ♠>♥>♣>♦」。但牌是**两副**:两家可以切到同花同点(两张 ♠A)。规则到这里断档。我加了确定性 tiebreak:再相同比牌 id(任意但可复现)。建议规则书补一句,或规定重切。

### H7. 发完牌后亮主窗口的起问座位

README `onDeal`:「发完之后还会绕圈再问,直到一整圈没人动作(上限 4 圈)」。**从谁开始问没写**(firstTaker?最后一张牌的收牌者的下家?庄家?)。我从 **firstTaker** 起绕圈。另外 RULES 里这个窗口是「默认 10 秒」的实时窗口(§S2 ②),README 产品化成 4 圈 —— 这个改写本身合理,但起问座位要定死,否则「最后一圈谁还有机会反」两种实现不同。

### H8. 甩牌被吃后的跟牌义务与抠底倍数按缩减后计算

§D:甩牌失败「只能出其中最小的那一组」。此后跟牌方的义务按**缩减后**的领出重算(张数、对子数、拖拉机义务全部按新领出)—— 规则书没明说,但这是唯一自洽的读法。同理,若**最后一墩**的领出是被吃的甩牌,§G 的「末墩每人出的张数」我按**缩减后**的实际张数算抠底倍数。建议两处都补一句。

### H9. §F 加固条款与「不能反自己」物理上重叠

§F:「加固:只有亮主的人自己能加固,同一花色」。两副牌里,亮主者已持有一张该花级数牌,**别家物理上不可能持有同花级数对**(另一张是唯一的),所以「非亮主者不可加固」其实不需要单列条件 —— `canOverride` 的「不能反自己」已覆盖。我的引擎单列了 `canReinforce` 前置条件,两种写法在实际对局中等价。不算洞,但规则书可以点破这一层,省实现者一次纠结。

## 2. 哪个判定最难实现

**`isLegalFollow` + 构造性合法跟牌(我的 `findLegalFollow`)**,没有之一。

难点不在 §S3 ⑤ 的伪码本身,而在三条义务**独立叠加**(§S6 #4)落到「构造一手合法牌」时的顺序:先按比例满足门内张数,再补足对子数 `min(need, have)`,再满足拖拉机长度(有长必跟、短的也要跟),最后填充剩余张数 —— 而填充时**不能破坏已经满足的义务**,还要兼顾「尽量不散对子」这类策略偏好。我在填充阶段出过一个真实 bug:极端牌型(手牌几乎全是对子)跟长甩牌时,填充逻辑每对只拆一张,凑不满领出张数 —— §S5 没抓到(见下),是我的随机器(4505 局景 × 5 种偏好全量校验 isLegalFollow)抓出来的。

第二难是 `decompose` 的相邻判定:必须先 `effSuit` 归门、再用 `ordIdx`(级数牌已从本门抽走)判**差恰为 1**。§S6 #2 和 #3 是联动的:打 7 时 ♥6♥6+♥8♥8 是拖拉机,打 2 时同样的牌是甩牌 —— 只用点数差必错一种。§S5 对这两条的向量覆盖很好,照着写就能对。

第三难是 `checkThrow` 的「任何一家(含**队友**)能压任何一个组件即失败」(§D 裁决细节第 1 条)—— 反直觉(队友的牌也能搅黄我的甩牌),但 §S5 没有覆盖这一情形的向量。

## 3. §S5 自测向量评价:够用,但有三个洞

总体评价:**牌序/牌型/跟牌义务/胜负/结算的向量质量很高**,照着实现 + 全过之后,我的引擎在 7000+ 局模拟里没出过任何规则性违规。但有三处我**写错过、§S5 没抓出来**:

1. **构造性填充不足**(上述 findLegalFollow bug)。§S5 跟牌向量全是 2–7 张的小手牌,不触及「填满 N 张」的构造路径。建议加:领出 6 张甩牌(2 对 + 2 单),手牌该门全是对子,验证能合法跟满 6 张。
2. **对局终止条件**。「打 25 墩」(H1)在引擎层面根本无法断言,§S5 自然没有向量 —— 但它是时序描述的错误,不是向量不足。改 §S2 即可。
3. **甩牌被吃后的连锁**(H8):缩减后的跟牌义务、末墩缩减后的抠底倍数,都无向量。建议加一条「末墩甩牌被吃 → 抠底倍数按缩减后张数」的端到端向量。

另外两条覆盖建议(非错误,只是没测到):甩牌判定**含队友**的情形;`partialTractorFollow` 的「短拖必须跟」已有向量 ✓ 很好。

## 4. README 接口评价:准确,三个小坑

README 的 view 字段表和实际对局完全一致,`history` 扁平结构的专门一节(「最容易写错的地方」)非常有用。小坑:

1. **example 的 follow 兜底会吃罚分**:`view.hand.slice(0, plays[0].cards.length)` 只保证张数,不保证跟门/跟对(§S3 ⑤ 第 2、3 条)。它是「能跑」示例不是「合法」示例,README 没有标注这一点。建议在示例旁加一行「这在有门不跟时会被罚,正式实现要用 §S3 ⑤」。
2. **罚分表缺「非法领出」行**(见 H4)。
3. **`played` 初值只在 RULES §S3 ⑧ 文末**(`[-1,-1]`),README 的字段表只说了含义。两处文档对照才能写对,建议 README 字段表补一句初值。
