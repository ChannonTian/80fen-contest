## 上手

```sh
# 这一对打了多少场、几比几
node season1/replay.js season1/plays/claude-opus-5__kimi-k3.ndjson.gz

# 第 7 副牌的两场(交换阵营),摊开四家手牌
node season1/replay.js season1/plays/claude-opus-5__kimi-k3.ndjson.gz 7 --hands

# 只看其中一场的第 3 局
node season1/replay.js season1/plays/claude-opus-5__kimi-k3.ndjson.gz 7 --side=0 --round=3
```

自己解就更自由:

```sh
# 谁在无主局里坐庄坐得最多
zcat season1/plays/*.ndjson.gz | jq -c '.rounds[] | select(.trump==null)' | wc -l

# 某人当庄输得最惨的十局
zcat season1/plays/gpt-5.6-sol__kimi-k3.ndjson.gz \
  | jq -c '.rounds[] | select(.defendersWin) | {seed:.seed, no, total}' | sort -t: -k3 -rn | head
```

格式见 [`FORMAT.md`](FORMAT.md)。

## 这份档案怎么来的

比赛当时**只记了逐局摘要**,没记逐墩 —— 当时的判断是「量太大,排名和申诉用不上」。
要公开整季对局,这份逐墩记录是**重跑出来的**。

重跑是不是同一场比赛,这件事没有靠承诺,是验过的:决策路径上没有 `Math.random`、
没有 `Date.now`,同种子必然同牌同走法。重跑出来的逐局记录和归档里那份
**逐字节比对**,9000 场全对。逐墩与逐局的一致性另有三重校验,每渲染一局都跑一次:

* 每局四家还原出来的手牌各 25 张,加上底牌 8 张,恰好一副 108 张
* `plays` 的长度 == 逐局记录里的墩数 `tricks`
* 逐墩加出来的闲家得分 == 逐局记录里的 `rawTotal`

## 这一季是带着两处已知偏差跑完的

裁判的实现和 [`../RULES.md`](../RULES.md) 不一致的地方就是**我们的 bug**,公开修。
第一赛季带着两处跑完了 —— **本季五份提交一次都没触发**(零违规、零崩溃),
所以当时压着没修:中途改判罚会让已跑的 258722 局失去共同基准。

**2026-09-07 两处都修了**,所以这一季的记录是按**旧**口径跑出来的。要拿它对照
自己的引擎时记得这一点;要参加第二赛季,这两格要按新规则书重新自查。

> ⚠️ **这份牌谱用现在的裁判是重现不出来的。** 逐墩记录是在**修之前**的裁判上重跑的
> ——只有这样才能和归档的逐局记录逐字节对上,也才是第一赛季真正打出来的那些牌。
> 换成修好的裁判,同一个种子会在那 0.0033% 的跟牌局面上分叉,之后整场就走散了。
> 牌谱记的是**当时发生了什么**,不是「现在重跑会发生什么」。

1. **`decompose` 的贪心断链** —— 同序号的对子会把本来连得上的链**切短**。现在分层。
   只影响跟牌义务里的「有长必跟」,实测主门手牌里 0.0033%;甩牌成不成立 0 次变化,
   `classify` 0 次变化。详见 `RULES.md` §S3 ③。
2. **领出不成型没有判罚** —— 领出混门(比如 ♥5+♦7)会让裁判自己抛 `TypeError`,
   整场作废、双方都不计,等于给「打不过就掀桌」留了一条出路。现在按
   「替出张数 × 5」罚,和跟牌不合法同一个口径。
